# Pawdy Workspace — ระบบสำรองข้อมูล (ฟรีทั้งหมด)

สำรอง 4 ชั้น ชั้นไหนพังก็ยังมีชั้นอื่นรอง ไม่มีค่าใช้จ่ายสักบาท ไม่ต้องผูกบัตร

| ชั้น | เก็บที่ไหน | ความถี่ | เก็บย้อนหลัง | กันอะไร |
|---|---|---|---|---|
| 1 | ในตัว Supabase (ตาราง `backups`) | ทุกคืนตี 0 | 90 วัน | **บั๊กแอปลบข้อมูล** ← เคสที่เพิ่งเกิด |
| 2a | Google Drive | ทุกวันตี 1 | 60 ไฟล์ | โปรเจกต์ Supabase หายทั้งก้อน |
| 2b | GitHub (private repo) | ทุก 6 ชั่วโมง | ทุกเวอร์ชันตลอดกาล | เผลอลบ / อยากย้อนดูว่าวันไหนเปลี่ยนอะไร |
| 3 | เครื่องของแต่ละคน | อัตโนมัติ | 7 วัน | เน็ตล่ม เข้าเซิร์ฟเวอร์ไม่ได้ |

ชั้นที่ 3 อยู่ใน `index.html` แล้ว ไม่ต้องทำอะไรเพิ่ม

---

## ชั้นที่ 1 · Supabase (ทำก่อน สำคัญที่สุด — ใช้เวลา 2 นาที)

ชั้นนี้กันเคสที่เพิ่งเกิดได้ตรงจุดที่สุด และกู้คืนได้เร็วที่สุด

1. เข้า Supabase Dashboard → **SQL Editor** → **New query**
2. เปิดไฟล์ `1-supabase-pg_cron.sql` ก๊อปทั้งไฟล์มาวาง → กด **Run**
3. ถ้าขึ้น error เรื่อง `pg_cron` ให้ไปที่ **Database → Extensions** ค้น `pg_cron` กด Enable แล้วรันใหม่
4. ท้ายสุดจะได้ `backup_id` กลับมา = ถ่ายสำเนาชุดแรกเรียบร้อย

**เวลาต้องกู้**

```sql
-- ดูว่ามีสำเนาวันไหนบ้าง
select id, at, note, n_tasks from public.backups order by at desc;

-- กู้แบบปลอดภัย เติมเฉพาะงานที่หาย ไม่แตะของที่ยังอยู่
select public.restore_backup(123);
```

**ก่อนจะทดลองอะไรเสี่ยงๆ** สั่งถ่ายสำเนาไว้ก่อนได้ทุกเมื่อ

```sql
select public.make_backup('ก่อนแก้ระบบ');
```

## ชั้นที่ 2a · Google Drive (ใช้เวลา 5 นาที)

1. เปิด [script.google.com](https://script.google.com) → **New project**
2. ลบโค้ดเดิมทิ้ง วางไฟล์ `2-google-drive-backup.gs.txt` ทั้งไฟล์
3. กรอก `CONFIG` 4 ช่องบนสุด
   - `SUPABASE_URL` กับ `SUPABASE_ANON_KEY` ก๊อปจาก `index.html` ในก้อน `PAWDY_CONFIG`
   - `LOGIN_EMAIL` / `LOGIN_PASSWORD` = อีเมลกับรหัสที่ใช้เข้าเว็บ
4. กด Save → เลือกฟังก์ชัน **backupNow** → **Run** → กดอนุญาตสิทธิ์
5. เช็คใน Drive จะมีโฟลเดอร์ **Pawdy Backups** พร้อมไฟล์แรก
6. เลือกฟังก์ชัน **enableDailyBackup** → **Run** (ตั้งเวลาให้ทำเองทุกวัน)

**เวลาต้องกู้** — โหลดไฟล์ `.json` จาก Drive → ใส่ใน `pawdy-restore.html`

## ชั้นที่ 2b · GitHub (ใช้เวลา 10 นาที)

1. สร้าง repo ใหม่แบบ **Private** ชื่ออะไรก็ได้ เช่น `pawdy-backup`
2. อัปไฟล์ 2 อันเข้า repo
   - `3-github-backup.py` → เปลี่ยนชื่อเป็น **`backup.py`** วางที่รากของ repo
   - `3-github-workflow.yml` → วางที่ **`.github/workflows/backup.yml`**
3. ไปที่ **Settings → Secrets and variables → Actions → New repository secret** เพิ่มทีละตัว 4 ตัว

   | ชื่อ | ค่า |
   |---|---|
   | `SUPABASE_URL` | จาก `PAWDY_CONFIG` |
   | `SUPABASE_ANON_KEY` | จาก `PAWDY_CONFIG` |
   | `PAWDY_EMAIL` | อีเมลที่ใช้เข้าเว็บ |
   | `PAWDY_PASSWORD` | รหัสผ่าน |

4. ไปแท็บ **Actions** → เลือก **Pawdy backup** → **Run workflow** เพื่อทดลองรันครั้งแรก
5. ถ้าเขียวแล้ว จะเห็นโฟลเดอร์ `backups/` โผล่ใน repo

**เวลาต้องกู้** — โหลด `backups/latest.json` (หรือไฟล์ของวันที่ต้องการ) → ใส่ใน `pawdy-restore.html`
กด History ของไฟล์ใน GitHub ก็ย้อนดูได้ว่าวันไหนข้อมูลเป็นยังไง

> ⚠ **ข้อควรรู้** GitHub จะปิดตารางเวลาอัตโนมัติถ้า repo ไม่มีความเคลื่อนไหว 60 วัน
> ถ้าใช้ GitHub เป็นตัวสำรองหลักตัวเดียว ควรเข้าไปดูแท็บ Actions เดือนละครั้งว่ายังรันอยู่
> หรือทำชั้นที่ 1 ควบไว้ด้วย เพราะ cron ในฐานข้อมูลไม่มีข้อจำกัดนี้

## เรื่องความปลอดภัยที่ควรรู้

ทั้ง Apps Script และ GitHub Actions ต้องเก็บรหัสผ่านของบัญชีที่ใช้อ่านข้อมูล
**แนะนำให้สร้างบัญชีแยกไว้ใช้เฉพาะงานนี้** เช่น `backup-bot@pawdy.co.th`
แล้วเพิ่มเข้าตาราง `members` ตามปกติ ถ้าวันหนึ่งรหัสหลุดก็เปลี่ยนแค่บัญชีนั้น

- Apps Script — โค้ดเห็นได้เฉพาะเจ้าของบัญชี Google ที่สร้าง
- GitHub — ต้องเป็น **private repo** และใช้ Secrets เท่านั้น อย่าพิมพ์รหัสลงในโค้ดตรงๆ

## กันพลาดที่ใส่ไว้ให้แล้ว

ทั้ง 3 ชั้น **จะไม่ยอมเขียนสำเนาถ้าดึงข้อมูลมาแล้วไม่มีงานเลย** — กันเคสที่แอปมีบั๊ก
แล้วสำเนาว่างๆ ไปทับสำเนาดีๆ ที่เก็บไว้ (ซึ่งคือสิ่งที่ทำให้เกือบกู้ข้อมูลไม่ได้รอบนี้)

ชั้นที่ 1 ยังข้ามการเก็บถ้าข้อมูลไม่เปลี่ยนจากเมื่อวาน จะได้ไม่เปลืองพื้นที่
และ Apps Script จะส่งอีเมลเตือนถ้าดึงข้อมูลมาแล้วผิดปกติ
